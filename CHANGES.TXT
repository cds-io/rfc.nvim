2026-10-20  A versioned render

  lua/rfc/help.lua
    RENDER numbers the render (3) and FOOTER writes it as every
    document's last line, after the modeline; render_of reads it back.

  lua/rfc/help_eip.lua
    A heading's title goes through plain as well, so its emphasis is its
    text in the heading, the contents and the tag.

  lua/rfc/store.lua
    has is true only for a document the current render wrote; raw reads
    the stored text.

  lua/rfc/init.lua
    ensure renders a missing or outdated document from the stored text
    when there is one, and fetches only when there is none; jump sends a
    tag whose document is missing or outdated through open before :help,
    so a cached document meets each render improvement on its next open,
    and a buffer still holding the earlier render is dropped first so
    :help shows the file just written.

  spec/
    render_of and the re-render case: 44 pure and 32 editor cases.

2026-10-20  Tables and inline markup in proposals

  lua/rfc/help_eip.lua
    A table, HTML as pandoc writes it or markdown, is laid out as aligned
    columns two spaces apart with a rule under a heading row, so no bar
    reads as a link. Every other body line goes through cds.eip.plain:
    inline HTML dropped, a code tag as backticks, entities unescaped,
    bold and emphasis as their text. A line that would start with <
    gets a leading space, since help hides a leading < as the end of a
    code block.

  lua/rfc/store.lua
    register retires the documents of the retired erc source (doc/erc*.txt
    and erc*.md) and rewrites the tags file, since the eip documents now
    define the alias tags those carried.

  lua/cds/eip.lua
    Vendored from ../cds: plain and tables.

  spec/
    Four render cases over ERC-1123's tables, emphasis, inline HTML and a
    leading <; one store case: 43 pure and 31 editor cases.

2026-10-20  :Eip, one command for EIPs and ERCs

  plugin/rfc.lua
    One command per source: :Rfc for the RFC Editor, :Eip for Ethereum's
    proposals. Each takes a number, a tag, words to search its own index,
    or nothing for its own picker, and completes over its own index and
    documents.

  lua/rfc/sources.lua
    The eip source covers both repositories, since EIPs and ERCs share one
    number space: its fetch asks ethereum/EIPs and, on the stub that says
    a proposal moved, ethereum/ERCs; its index is both listing pages as
    one text, each number once; erc is its alias prefix, so a tag by
    either name resolves to it.

  lua/rfc/help_eip.lua
    render(id, lines): every proposal is tagged eip<number>, and one in
    the ERC category carries erc<number> as a second tag on its first
    line.

  lua/rfc/init.lua
    pick, candidates and complete take the sources they cover; command
    builds a source's command and completion.

  lua/rfc/config.lua
    sources: rfc and eip.

  spec/rfc_nvim_spec.lua
    30 editor cases, :Eip and the alias among them.

  Thanks to @gnidan, whose feedback shaped this: :Rfc for the IETF
  alone, :Eip for the proposals, and no ERC to tell apart from an EIP.

2026-10-20  Search and completion

  lua/rfc/init.lua
    pick takes a query and offers the entries whose number or title
    fuzzily match it, opening a single match at once; candidates reads
    every enabled source's cached index (parsed once per version of the
    file) and every tag of every cached document; complete fuzzily
    matches the typed text against them. The picker and completion show
    an entry as its tag, two spaces, its title.

  plugin/rfc.lua
    :Rfc takes words to search as well as a number or a tag, completes
    with rfc.complete, and reads the first word of a completed item as
    the tag.

  spec/rfc_nvim_spec.lua
    Seven cases over the search and the completion; 29 editor cases.

2026-10-20  Ethereum proposals as sources

  lua/rfc/sources.lua (rim)
    A source is one record: prefix and label, where its text and index
    come from, how the index reads into entries, and how the text
    renders. rfc is the RFC Editor; eip and erc come from one
    constructor over a GitHub repository and a listing page.
    sources.all orders the picker; sources.of names a tag's source.

  lua/rfc/help_eip.lua (pure)
    render(prefix, id, lines) is total: the file tag line with the
    frontmatter's title (an ERC also carries its EIP number as a tag), a
    header of status, type, category and created, the requires as
    links, the author, a CONTENTS of links to every heading indented by
    level, each heading tagged by its slug (level two in capitals, a
    repeated heading numbered), fenced code as help code blocks, every
    EIP or ERC the text names as a link, and a moved stub linking to
    where it went.

  lua/rfc/config.lua
    sources: which of rfc, eip and erc :Rfc reads; rfc alone by
    default.

  lua/rfc/init.lua
    open, ensure and the picker take a source; jump reads a tag's
    source by its prefix, fetches on E149 when the source is enabled
    and says which setting to enable otherwise; the picker lists every
    enabled source's index, RFCs then EIPs then ERCs.

  lua/rfc/store.lua
    Documents are named by their tag, with the text stored under the
    source's extension; the index file is the source's.

  lua/rfc/fetch.lua
    proposal (a markdown file in a repository) and listing (a page).

  lua/rfc/help.lua
    tags_in reads every tag shaped as a prefix and a number, whichever
    source wrote it; slug, with_tag and MODELINE are shared.

  lua/cds/eip.lua
    Vendored from ../cds.

  plugin/rfc.lua
    :Rfc takes a number, any source's tag, or nothing.

  spec/
    11 pure cases over the EIP render and 7 editor cases over the
    Ethereum sources, with EIP-1, EIP-1559, ERC-20, the moved EIP-20
    stub and excerpts of both listing pages as fixtures: 39 pure and 22
    editor cases in all.

2026-10-19  RFCs as help documents

  cds.rfc (pure; the house library's RFC reader, specced in ../cds)
    contents: the table of contents as sections (number, printed label,
    title, heading line, row line), empty for a text without one; rows
    in the four shapes RFCs use
    (numbered, Appendix A., B.1., unnumbered at the top-level indent),
    wrapped titles joined, running headers and footers inside the ToC
    skipped, and the ToC ending where its first section begins.
    references and cited_rfc: the References section's entries and the
    RFC an entry cites. mentions: every "[RFC2616]", "RFC 2616",
    "Section 3.1 [of RFC n | of [CIT]]" and "[CIT]" on a line with the
    byte span a link replaces. index: the RFC Editor's index as entries
    with label, obsoletes, obsoleted_by and formats.

  lua/rfc/help.lua (pure)
    render(rfc_num, lines) is total: it answers a help document for any
    text, with the file tag on line 1, a tag at column 78 on every
    heading the ToC names and on every entry of the references, each
    ToC row's number as a link to its heading, and the body's "Section
    3.1", "Section 14.4 of [RFC2616]", "RFC 2616", "[RFC2616]" and
    "[CACHING]" as links; a same-document section links only when its
    heading was found. title reads the centred title after the header
    block; clean turns a fetched body into lines; tags_in reads a
    document's tags back and tags_file writes the sorted tags file the
    store keeps, so a stray *tag* in an RFC's text never becomes one.

  lua/rfc/store.lua (rim)
    The cache directory as a runtimepath entry: the text as fetched, the
    document under doc/, the tags file rebuilt from every document, and
    the index with its day-long freshness.

  lua/rfc/fetch.lua (rim)
    The RFC Editor over cds.http as Tasks; a 404 reads as the RFC not
    existing.

  lua/rfc/init.lua (rim)
    open (fetch, clean, render, write, then :help, as one Task tracked in
    the activity segment), jump (:help with a fetch on E149 for an RFC
    tag not in the store), follow and follow_line for CTRL-] and <CR> in
    the plugin's help buffers, pick for the index, attach for the keys
    and the requirement-keyword highlight, notify through the reader's
    handler, and activity for the statusline.

  lua/rfc/config.lua
    cache_dir and notify.

  lua/cds/
    task, async, proc, http, activity and rfc, vendored from ../cds,
    the house library's one source, by make vendor; make check refuses a
    copy that differs. Fenced from stylua in .styluaignore.

  plugin/rfc.lua
    :Rfc takes a number, a tag or nothing; a FileType autocmd attaches
    the keys to the help buffers the store owns.

  spec/
    28 pure cases over the render (the reader's 30 run in ../cds),
    15 editor cases over
    the command, :help, the keys and the index, with the store in a
    temporary directory and the network replaced by fixture text.
    make check runs both tiers, selene and stylua.
